# 능력 설정과 등록 계약

2026-10-11. 설정을 사용하는 능력의 기본값·타입·범위는 `config/AbilitySpecs.kt`와 여기에 합치는 `config/specs/*Specs.kt`에서 정의한다. 새 설정을 추가할 때 해당 정의와 사용하는 handler를 함께 변경한다. 능력 객체 생성은 서버·플러그인 조회나 작업 시작을 하지 않으며, bootstrap의 `AbilityManager.initialize(plugin)`에서 소유 플러그인을 연결하고 설정 검증 뒤 start를 호출한다.

## 저장과 실행

- 기존 파일을 strict YAML로 읽고 복사본에서 누락 필드만 보완한다. 0/false는 명시적 값이다. 알 수 없는 사용자 필드는 보존한다.
- schemaVersion은 누락/1만 허용한다. 알려진 모든 필드와 교차 조건이 통과한 뒤에만 누락 기본값/schema를 원자 저장한다. 잘못된 타입·값·YAML·미래 schema는 원본 파일을 덮어쓰지 않고 시작 실패에 파일 경로를 포함한다.
- 실행 handler는 불변 AbilitySettings를 읽는다. asConfiguration은 독립 복사본이며 런타임 값을 변경하지 못한다. 외부 파일 변경을 실행 중 자동 적용하지 않는다.
- 정수는 Int/Long 원본만 허용하고 Int 범위를 확인한다. 확률은 0..1, 공간 범위는 최대 128, 물리 속도 등은 최대 64, 반복 주기·나눗셈의 분모는 양수를 요구한다. 정확한 필드별 경계는 AbilitySpecs를 기준으로 한다.
- 레일건의 지연 0과 소수 가속 시간은 지원한다. 수명/지연 합계, 점프 게이지 곱셈, 통달 종료 시각은 Int overflow를 사전 거부한다. 연금술 가중치 합은 1이어야 한다.
- 에메랄드 수리량 0, 쿠키 지속 시간/레벨 0, 통달 지속 시간 0은 해당 효과를 비활성화한다. 통달 저항/신속 레벨 0은 해당 포션을 생성하지 않는다. 무료 부스터 비용 0은 정상 동작한다.
- Titan은 자체 설정을 사용하지 않으므로 빈 titan.yml 생성을 중단한다. 기존 파일을 삭제하지 않는다.

## 다시 불러오기와 기본값 안내

`/ability reload`는 `limpi.ability.admin.reload`(default op) 권한으로 콘솔에서도 사용한다. 모든 spec의 `ability/<code>.yml`을 strict YAML로 읽어 검증하고, 하나라도 실패하면 파일명·사유를 모아 표시하며 기존 런타임 설정과 파일을 모두 보존한다. 성공할 때만 모든 설정 객체를 같은 메인 스레드 명령 실행에서 교체한다. 파일의 누락 값은 런타임 기본값으로 보완하지만 reload는 파일을 쓰지 않는다.

능력 상세 설명 캐시는 불변 설정 객체가 바뀔 때 다시 만든다. 이미 열린 도감은 다시 열어야 갱신된다. 설정과 무관한 Registry·Sound·PotionEffectType의 lazy 초기화는 유지한다.

반영 시점과 제한:

- `AbilityRunnable`은 생성 시 해당 능력의 설정을 보관한다. callback·충전·반격·은폐·매의 눈 표식·포탄·통달·시간 역행도 시작 시 불변 설정을 보관한다. 진행 중 효과와 그 효과에서 파생한 작업은 기존 값을 사용하고 새 시전부터 새 값을 사용한다. UUID 세션 설정도 효과 종료/사망/능력 변경/이탈/stop에 함께 정리한다.
- 활성화되지 않은 패시브의 다음 공격·채굴·재생 이벤트와 전역 게이지/장탄 재생 틱은 새 값을 읽는다. 저장된 게이지 값과 이미 적용한 Bukkit 쿨타임·포션을 재로드가 초기화하지 않는다. 마지막 사용 시각으로 직접 계산하는 쿨타임은 다음 입력에서 새 설정을 읽는다.
- 시간 역행의 실행 중 기록 버퍼는 기존 길이를 유지한다. 다음 역행 시 새 이동·회복·쿨타임 값을 쓰고, 역행 뒤 새 기록 버퍼부터 새 `rewind_ticks`를 적용한다.
- **능력 아이템 캐시(activeItem)와 그 로어는 재시작 후 반영한다.** WebShooter의 range, TimeLeaper 계열의 rewind_ticks/cooldown_ticks 표시가 해당한다. activeItem의 직렬화 메타데이터도 물품 보호 판정에 쓰므로 재로드로 기존 아이템의 인식을 바꾸지 않는다. 동작 수치는 다음 사용부터 새 값을 읽는다. 재로드는 live 인벤토리를 직접 수정하지 않는다.

서버 시작 시 검증된 능력 파일에 `_defaults.<key>`로 이번 버전 기본값을 기록한다. 이전 기록이 있고 실제 값이 그 이전 기본값과 같으며 새 기본값과 다를 때만 파일·키·현재/새 기본값을 로그로 알린다. 값을 자동 교체하지 않고 사용자 값과 알 수 없는 필드는 보존한다. 이전 기록이 없는 기존 파일은 첫 실행에서 기준만 기록한다. 다음 시작부터 비교하며 같은 변경 안내는 반복하지 않는다.

## 검증 범위

전체 시험 수와 빌드 결과는 [구현 기록](IMPLEMENTATION_LOG.md)을 따른다. 설정 시험은 전체 기본값, 부분 설정, 0/false 보존, 불변 값, 손상 원본 보존, 타입·범위·교차 조건, 실제 능력 레지스트리의 서버 없는 생성, 전부 검증 전 파일 무변경, 실제 능력 details 캐시 갱신·이전 snapshot 보존, 기본값 변경 안내 조건을 확인한다. 진행 중 Paper 작업의 실제 효과·화면은 [서버 시험 계획](SERVER_TEST_PLAN.md)의 NEXT-03에서 확인한다.
