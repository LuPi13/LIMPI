# 설탕 소비·결과·적용

2026-10-10. 설탕도 common removal의 37칸 양손 checkpoint를 사용한다. 실제 손/원본 payload를 선행 복구 뒤 재확인하고 1개만 소비한다. useItem DENY·blocked·지속 시간 0에서는 소비하지 않는다.

- 효과 key·기간·월드·범위·주변 대상 UUID를 소비 전에 고정한다. 영역 확률은 `<` 비교로 0과 1 경계를 보장한다. 소비를 저장한 뒤 pending 결과와 원장을 한 commit에 기록한다.
- 소비 직후 중단되면 접속/claim 복구에서 원래 결과를 사용한다. 설정이나 registry 순서 변경으로 재추첨하지 않는다. 알 수 없는 효과 key는 임의 대체하지 않고 오류로 보고한다.
- 본인에게는 획득한 결과를 적용한다. 범위 효과는 미리 선택된 최대 256개 대상만 재확인하고, 살아 있는 적/동일 월드/실제 구면 범위/PvP·Creative·Spectator·blocked 조건을 따른다. 새 주변 대상에게 과거 결과를 적용하지 않는다. 설명의 범위 `/2` 표기를 실제 범위로 수정했다.
- 이 효과는 소비 보상이므로 능력 변경만으로 제거하지 않는다. Paper의 포션 변경 취소를 존중한다.

## 적용할 수 없는 결과

접속/claim 복구에서 대기 결과를 읽을 수 없거나(손상/중복) 효과 key가 더 이상 registry에 없으면 결과를 남긴 채 오류를 기록하고 건너뛴다. 매 접속 kick으로 잠그지 않는다. 대기 결과가 남아 있는 동안 새 설탕 사용은 거부된다. 관리자는 `/financial sugar <owner UUID>`로 조회하고, 소유자가 오프라인일 때 `/financial sugar void <owner UUID> <결과 UUID> <근거>`(`limpi.financial.admin.sugar`)로 **환불 없이** 대기를 종료한다. sugar_result와 actor/근거 영수증은 보존되고 이후 적용 권리는 발급되지 않는다. 같은 요청은 한 번만 종료한다.

## 즉시 효과의 한계

SQLite commit과 live 포션/즉시 피해/회복은 원자적으로 묶이지 않는다. 따라서 **적용 권리를 먼저 한 번만 발급하고 그 뒤 실제 효과를 적용**한다. 권리 발급 commit 실패면 pending이 유지되고 재시도할 수 있다. 권리 발급 직후 프로세스 중단 또는 일부 대상 적용 실패면 결과/원장은 남지만 적용을 자동 반복하지 않는다. 이 좁은 구간에서 효과가 생략될 수 있으며, exactly-once 피해/회복을 보장하지 않는다. live 적용 실패는 거래 UUID를 포함해 경고한다. 이전 sugar_result와 UUID 원장으로 소비/발급 사실을 감사할 수 있다. 관리자 제거 판정도 한 결과만 생성한다.

전체 296개 시험과 test build가 통과했다. 새 7개 시험은 손 회수/결과 고정, 소비 저장 직후 중단/재시작, 적용 권리 후 중단의 재실행 방지, 권리 commit 실패, 결과 변경/중복 소비/잘못된 대상 거부, 관리자 판정을 확인한다. 실제 Paper 효과·보호/중첩 이벤트 및 물리 저장은 최종 서버 시험에서 확인한다.
